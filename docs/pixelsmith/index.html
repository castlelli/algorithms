02 · Inside a block

How 64 pixels become a few bits

The codec cuts the image into 8×8 blocks and rewrites each one as a sum of 64 cosine patterns. Most of the weights are close to zero. Dividing them by a quality table rounds those to exactly zero, and long runs of zeros cost almost nothing to store. Hover the image to pick a block.

  1. 1Pixels minus 128

  2. 2DCT weights of 64 patterns

  3. 3÷ table, rounded the lossy step

  4. 4Back again what you see

  5. 5Zigzag and runs low frequencies first, zeros counted not stored

The 64 patterns

Every 8×8 block in every JPEG is a weighted sum of these. Switch patterns off and watch what the image loses: the top-left one is the average brightness, the rest add detail, finer toward the bottom right.

03 · Quality

What each byte buys

The same image encoded at every quality, measured against the original. PXS uses tables fitted to each image (optimized Huffman), so for the same error it usually needs fewer bytes than a baseline JPEG encoder with fixed tables. Computed now, on the image in the studio.

04 · Command line

The same engine, in your terminal

Pixelsmith is a small C11 library with no dependencies beyond the C library (image files are read and written with the public-domain stb headers, included). One binary, every tool.

Build
git clone https://github.com/castlelli/algorithms
cd algorithms/pixelsmith
make          # builds ./pixelsmith
make test     # unit tests, with sanitizers
Use
pixelsmith compress photo.png photo.pxs -q 75
pixelsmith decompress photo.pxs back.png
pixelsmith resize photo.png small.png --fit 800x800
pixelsmith quantize photo.png gif-like.png --colors 16 --dither bayer
pixelsmith compare photo.png back.png --diff diff.png
Commands
compress
PXS (DCT + Huffman, 4:2:0 or 4:4:4, quality 1–100) or the classic text format
decompress
PXS or classic text back to any image format
convert
PNG, JPEG, BMP, TGA, PXS; reads GIF, PSD and PNM too
resize
nearest, bilinear, bicubic, Lanczos-3, in linear light
crop · rotate · flip
lossless quarter turns; any angle with transparent corners
adjust
brightness, contrast, gamma, saturation, hue, temperature
effect
grayscale, invert, sepia, threshold, auto levels, equalize, posterize
filter
Gaussian blur, unsharp mask, Sobel edges, emboss, median, pixelate
quantize
median-cut palette, Floyd–Steinberg or Bayer dithering
info · compare
histogram, PSNR, MSE, SSIM, difference map
The .pxs format
  1. PXS1magic
  2. v · flags · n · qversion, 4:2:0, channels, quality
  3. width · heightu32 each
  4. quant tables64 B per luma / chroma
  5. Huffman tablesDC + AC, canonical
  6. payloadY blocks, then Cb, then Cr
